# ТЗ: AI Worklog

## 1. Назначение

AI Worklog — обязательный пользовательский экран, а не приложение к README. Он должен доказывать, что разработчик управлял AI-инструментами, проверял результаты и принимал решения самостоятельно.

Маршрут: `/ai-worklog`. Пункт навигации виден из любого экрана приложения.

## 2. Источник данных

Worklog хранится в `src/shared/config/worklog.ts` как типизированный объект. Это осознанно статический контент: он описывает создание демо, а не предметные данные оператора. Запрещено получать его из mock API или дублировать в JSX.

```ts
type AiWorklog = {
  generatedAt: string;
  tools: { name: string; purpose: string; tokenCount?: number | null }[];
  totalDurationMinutes: number;
  tokenSummary: string;
  stages: WorklogStage[];
  decisions: string[];
  aiCorrections: Correction[];
  futureImprovements: string[];
};

type WorklogStage = {
  name: string;
  durationMinutes: number;
  developerWork: string[];
  aiWork: string[];
  keyPrompts: string[];
  outcome: string;
};
```

## 3. Обязательное содержание

Экран показывает:

1. Использованные инструменты, их роль и известные токены.
2. Общее фактическое время разработки.
3. Общую статистику токенов. Если инструмент её не показывает — точную фразу: «Инструмент не предоставляет статистику токенов; токены не считались».
4. Этапы: ТЗ и декомпозиция, архитектура, UI, mock API и алгоритм, тестирование, финальная проверка.
5. По каждому этапу: что сделал разработчик, что предложил/сделал AI, краткие ключевые промпты и результат.
6. Три–пять самостоятельных решений разработчика.
7. Хотя бы один случай, где AI ошибся, предложил лишнее или был исправлен вручную. Если таких случаев реально не было, написать это прямо, не выдумывая пример.
8. Три–пять реалистичных улучшений для production-версии.

Ключевые промпты передаются только как короткая суть запроса. Не хранить скрытые рассуждения модели, служебные сообщения, API-ключи, персональные данные или длинные чаты.

## 4. UI

Экран состоит из:

- hero-блока: «AI Worklog», итоговое время, токены, дата последнего обновления;
- таблицы или списка использованных инструментов;
- вертикальной timeline этапов;
- у каждого этапа раскрываемые блоки «Сделал разработчик», «Помог AI», «Ключевые промпты»;
- отдельных карточек «Мои решения», «Что исправлено вручную», «Что улучшить в продукте».

Использовать существующие shadcn `Card`, `Badge`, `Tabs`/`Collapsible` только при необходимости. Контент должен читаться на мобильном экране без горизонтального скролла.

## 5. Процесс ведения

- В начале работы создать скелет с пустыми значениями, а не выдумывать числа.
- После каждого завершённого этапа внести факт: время, действия, полезный prompt и собственное решение.
- Перед сдачей сверить Worklog с git history, тестами и README.
- Поле `generatedAt` обновить в день финальной проверки.
- Если часть работы делалась без AI, это указывается явно.

## 6. Definition of Done

- Worklog открывается без README и внешних ссылок.
- Все обязательные разделы заполнены фактами.
- Нет вымышленных токенов, времени, ошибок AI или «самостоятельных решений».
- Указано как минимум одно ручное исправление или честно указано его отсутствие.
- AI Worklog отражает финальное состояние приложения, а не план до начала разработки.
