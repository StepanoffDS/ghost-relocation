# Инструкции для AI-агентов

## Обязательное чтение

Перед любой работой прочитать в таком порядке:

1. [task.md](task.md) — исходные требования MOX.
2. [README.md](README.md) — границы, сценарий и критерии готовности.
3. [docs/backend.md](docs/backend.md) — если затрагиваются API, OpenAPI, MSW, данные или алгоритм.
4. [docs/frontend.md](docs/frontend.md) — если затрагиваются React, UI, FSD, роуты, состояние или тесты.
5. [docs/ai-worklog.md](docs/ai-worklog.md) — после каждого этапа реализации и перед финальной сдачей.

Если задача пересекает несколько областей, читать все относящиеся документы до изменений. Эти файлы — источник правды; при конфликте сначала уточнить задачу у пользователя, а не угадывать.

## Границы

- Это React/Vite SPA.
- Использовать Tailwind CSS и локально установленные компоненты shadcn/ui.
- Реальный сервер, БД, auth, JWT, cookies, WebSocket и AI API не реализовывать без явного запроса пользователя.
- Mock API строится только на MSW + `openapi-msw` + `openapi-typescript` по `docs/backend.md`.
- На этом этапе разрешена только документация: не инициализировать React-проект и не устанавливать зависимости, пока пользователь не попросит реализацию.

## OpenAPI и mock API

- Сначала изменить YAML-контракт, затем запустить генерацию типов, потом изменять handler и frontend API-hook.
- `generated.ts` не редактировать вручную.
- UI не импортирует MSW handlers, store или seed-данные.
- Business-правила подбора хранятся в чистой функции mock domain и покрываются тестами.
- Не добавлять авторизацию: её нет в тестовом задании.

## FSD

- Соблюдать слои `app → pages → widgets → features → entities → shared`.
- Импортировать сегменты только через их публичный `index.ts`.
- `shared` не зависит от верхних слоёв; `entities` не импортируют `features`.
- Не создавать абстракции, папки или зависимости «на будущее».
- Серверное состояние — TanStack Query; сложное локальное UI-состояние — `useReducer`/Context. Не добавлять глобальный state manager без необходимости.

## Качество

- Писать компактный TypeScript в стиле существующего проекта.
- Для изменений логики добавить минимальный тест; для UI проверить loading, empty, error и mobile состояние, если применимо.
- Не хранить секреты и токены в коде.
- Не сообщать о завершении, пока не выполнены релевантные lint, typecheck, tests и build.
- Учитывать пользовательские незакоммиченные изменения и не перезаписывать их.

## AI Worklog

- После завершённого этапа обновлять `src/shared/config/worklog.ts` фактическими данными.
- Не выдумывать время, токены, ошибки AI или ручные решения.
- Не записывать скрытые рассуждения модели; сохранять только краткие ключевые промпты и проверяемый результат.
